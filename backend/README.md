# AI-Powered Certificate Verification & Fraud Detection System

> AI-based preliminary verification and fraud-risk prediction for educational
> certificates. This system performs **AI-based preliminary verification** and
> outputs a **fraud-risk prediction** — it does **not** guarantee legal or
> document authenticity.

## Problem Statement

Forged and tampered educational certificates are a growing problem for employers,
institutions, and admissions offices. Manually checking every certificate is slow,
subjective, and does not scale. There is a need for an automated, reproducible
**preliminary** screening step that flags documents as **likely genuine** or
**suspicious** based on document structure, extracted fields, and statistical
patterns.

## Objectives

- Accept certificate uploads (PDF, PNG, JPG/JPEG).
- Extract usable fields and structural/visual signals.
- Run a trained ML model that predicts fraud risk.
- Return a human-readable verification result with a risk/confidence score.
- Store and monitor verification results (MLOps).
- Reproduce model training from a documented pipeline.

## Proposed Solution

A FastAPI backend that:

1. Validates and safely stores the uploaded file.
2. Extracts text (PDFs) and visual/layout features (PDFs and images).
3. Builds a fixed feature vector (see `Feature Set` in `docs/PROJECT_REPORT.md`).
4. Runs a trained Random Forest / Logistic Regression classifier.
5. Returns `prediction`, `risk_score`, `confidence`, `model_version`, and stores the
   result in a database.

A React (Vite) frontend provides the upload → verify → result experience.

**Important:** the model is trained on **synthetic/prototype data** and provides a
*prediction of fraud risk*, not a legal authenticity verdict. Always combine with
manual review for high-stakes decisions.

## Dataset Strategy

There is **no suitable public dataset** of real educational certificates with
fraud labels. This project therefore uses a **synthetic, reproducible dataset**
generated by `backend/src/data/make_dataset.py`.

- ~2,400 records, deterministic random seed (`TRAINING_SEED=42`).
- Genuine records follow realistic field patterns; fraudulent records are generated
  by deliberately violating patterns (bad IDs, unknown issuers, inconsistent marks,
  suspicious keywords, missing seals/signatures, blank/odd visuals, etc.) with some
  label noise so the problem is not trivially separable.
- All data is synthetic — **no real certificates or personal data are used.**
- Sample demo PDFs/images are generated locally for the UI demo
  (`backend/scripts/generate_samples.py`).

## ML Methodology

1. `src/data/make_dataset.py` → `data/raw/certificates.csv`
2. `src/features/build_features.py` → engineered features → `data/processed/features.csv`
3. `src/models/train_model.py` → Random Forest & Logistic Regression with
   `train/validation/test` split (no leakage, `random_state=42`)
4. `src/models/evaluate_model.py` → accuracy, precision, recall, F1, confusion matrix
5. Best model serialized to `models/artifacts/` with versioned metadata +
   preprocessor (feature list + scaler)
6. `src/inference/predict.py` → single-record prediction + risk score
7. Lightweight experiment tracking logs params/metrics/artifacts under
   `monitoring/mlruns/`

Metrics of interest for fraud detection: **precision, recall, F1** (not just accuracy).

## MLOps Workflow

- **Reproducible data** — seeded generator, versioned raw/processed outputs
- **Reproducible training** — one command, fixed seed, pinned artifacts
- **Experiment tracking** — JSONL run log (params/metrics/artifacts + model version)
- **Model versioning** — metadata JSON (`model_version`, feature list, metrics,
  timestamp) alongside artifacts; runtime reports the version used
- **Inference API** — `POST /api/verify`
- **Logging** — structured request/error logging to `monitoring/`
- **Basic monitoring** — `/api/metrics`: prediction count, class distribution,
  confidence distribution, model version usage, errors
- **Tests** — pytest suite covering preprocessing, features, model, API
- **Docker + CI** — containerized backend/frontend, GitHub Actions runs tests

## Installation

Requirements: Python 3.13, Node.js 18+ (for the frontend), Docker (optional).

Backend:

```bash

python -m venv venv
# Windows:
venv\Scripts\activate
# macOS/Linux:

pip install -r requirements.txt

```

## How to Train the Model


## Limitations

- The model is trained on **synthetic/prototype data**; performance on real
  certificates is not validated.
- This is a **preliminary AI-based verification** only — it does **not** provide a
  legal authenticity verdict.
- Image text extraction (OCR) is not included by default; image-based features are
  structural/visual. OCR can be added (e.g., pytesseract) if needed.
- No real-world labeled fraud data — a labeled feedback loop would improve accuracy.

## Future Improvements

- OCR integration for image text extraction
- Feedback capture (human review labels) and drift monitoring on real traffic
- Additional document sources (scanned PDFs, multi-page documents)
- Model registry integration (MLflow) when a tracking server is available
- Authentication/authorization for the verification endpoint
- Deployment hardening (managed reverse proxy, HTTPS) for production
